## Open it without installing anything

1. Extract the ZIP.
2. Open `docs/index.html` in your browser.
3. Use the navigation and buttons to visit the other pages.

The `docs/` folder is a ready-built HTML/CSS/JavaScript preview. It uses local images and does not depend on a CDN, remote fonts or a database. It is generated by the included static builder, **not** by a Next.js production build.

## Put the preview on your GitHub repository

Your repository is called `Pool-Up` in the screenshot.

1. Upload the **contents** of this project folder to the repository root. Do not upload the ZIP itself, and do not nest the whole project inside another folder.
2. Keep the `docs` folder intact. The root should contain `package.json`, `app`, `content`, `public`, `scripts` and `docs`, among the other project files.
3. For the preview, open **Settings > Pages**.
4. Select **Deploy from a branch**, branch **main**, folder **/docs**, and save.
5. Use the URL GitHub displays after publishing. The preview pages use relative links and work under the repository name.

This publishes a website preview. It does not deploy a booking or payment backend.

If you already uploaded the first Next.js project, replace its matching files with these. The old `app/data.ts`, `app/globals.css`, and old header/footer components are no longer used by this version and may be removed. Do not remove unrelated work from your repository.

GitHub's instructions: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## What is deliberately not live

- All form fields and submit buttons are disabled. No form data is collected, saved or sent.
- There is no authentication, identity verification service, driver approval backend or automatic matching.
- There is no credit balance, payment gateway, refund processing or driver payout system.
- The safety-reporting form is not monitored and is not an emergency channel.
- The policy pages are the descriptions you supplied, not complete or approved legal terms.
- Email, WhatsApp and support hours remain unspecified.

A visible preview notice distinguishes the supplied service copy from an operational service. There are no invented registration counts, savings figures, testimonials, verified drivers or partner logos.

After changing content, styles or public contact details, regenerate the preview:

```bash
npm run build:static
npm run check:content
```

These two commands use only Node.js. They do not require `npm install`. Use Node.js 22 or newer for the included scripts.

To serve the preview locally with Node.js:

```bash
npm run preview
```

Then open `http://localhost:3000`.

## Optional Next.js development

The project retains Next.js App Router source so a developer can extend it later.

```bash
npm install
npm run typecheck
npm run dev
```

Production static export:

```bash
npm run build
npm start
```

`next build` generates `out/`. The `start` script serves that static export with the included local server. This project uses `output: 'export'`, so it intentionally does not use `next start`.

For a Next.js export hosted under a repository path, set `NEXT_PUBLIC_BASE_PATH=/Pool-Up` before building. Leave it empty for a root domain or local development. The ready-built `docs/` preview does not require this setting.

Next.js export documentation: https://nextjs.org/docs/app/guides/static-exports

### Build verification boundary

The dependency-free static site was generated and checked here. All 28 pages were rendered in Chromium at 1440px, 768px and 390px; links, image paths, form-disabled states, layout overflow and menu/FAQ interactions were checked. All 28 HTML pages also passed local HTTP serving checks.

Five TSX files passed TypeScript syntax/transpilation checks. **A full Next.js dependency installation, semantic typecheck and production build could not be run in this environment because the package registry was unavailable.** Run the Next.js commands above before relying on that build. ## Before accepting real users

- Confirm the contact details, business history, availability and partnership wording.
- Complete the operational and professional reviews described in your brief.
- Provide completed, reviewed policies before collecting registration data or taking payments.
- Implement secure form submission, appropriate access controls, privacy notices and data handling.
- Keep identity documents, emergency-contact details and accessibility information out of the public repository.
- Connect approved payment and verification processes before showing any live balances or verification status.
- Remove the preview banner only after the represented services are actually ready. Removing the banner does not enable the forms or payments.

Public contact details belong in `config/site.mjs`. Secrets do not. The `.gitignore` excludes environment files and dependencies.
